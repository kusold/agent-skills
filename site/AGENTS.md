# AGENTS.md — docs site

Guidance for the Hugo site in this directory, published to Cloudflare Pages at <https://skills.mikekusold.com/> (custom domain on the `kusold-agent-skills` Pages project). For repository-wide guidance (skill format, `docs/` layout, installation), see the [root AGENTS.md](../AGENTS.md).

`hugo.toml` mounts `../docs` and `../skills` as site content, so skill guides and `SKILL.md` references render from the repo as-is — nothing is copied into `site/` except the landing page (`content/_index.md`) and the theme submodule. The landing page's "Available Skills" list and the site sidebar are both generated from the docs pages' front matter, so a new skill appears on the site automatically once `docs/{skill-name}/index.md` exists — flat, or nested in a mirrored group (e.g. `docs/languages/nix/`) with a group `_index.md` carrying `bookCollapseSection: true` so the group renders collapsible in the sidebar.

- Local preview: run `hugo server` from the `site/` directory (requires Hugo extended ≥ 0.158; on NixOS: `cd site && nix-shell -p hugo --run 'hugo server'`). Build from inside `site/` — invoking `hugo -s site` from the repo root writes some outputs to a stray root-level `public/`. Clone with `--recursive` to get the theme submodule (`themes/hugo-book`).
- Theming: colors are the Rosé Pine palette (auto light/dark), set in `assets/styles/custom.css` — hugo-book's supported override hook, which shadows the theme's stub. It depends on the explicit `assets` mount in `hugo.toml` (declaring mounts discards Hugo's default mounts). `layouts/_partials/docs/html-head.html` shadows the theme partial to set the `theme-color` metas and to run a pre-paint script that applies the visitor's saved choice from `localStorage` (`book-theme`; `auto` = system is the default — the API is `window.bookTheme`). `layouts/_partials/docs/brand.html` shadows the theme partial to place the Light/Dark/System dropdown (in `layouts/_partials/docs/theme-toggle.html`) to the right of the brand title; its icons live in `assets/icons/` and are re-tinted by the theme's `--icon-filter` like the bundled ones (served via the `docs/icon` partial — no shadow needed). The GitHub menu link gets its icon through the theme's `bookicon` menu param in `hugo.toml`. Re-sync the shadowed partials from the theme on submodule updates.
- Skill links: `layouts/_partials/docs/links/portable-link.html` shadows the theme partial so relative links to `skills/{path}/SKILL.md` from docs pages render as the GitHub blob view (`BookRepo` + `/blob/main/`) instead of the mounted content page; on GitHub the relative links work as-is. `layouts/_partials/docs/inject/content-before.html` adds a GitHub icon + `skills/{path}` breadcrumb at the top of each skill's docs page — flat (`skills/{name}`) or grouped (`skills/languages/nix/{name}`) — linking to the repo directory (rendered only when a matching `skills/{path}/SKILL.md` content page exists). Re-sync both from the theme on submodule updates.
- Deploy: pushing to `main` (or opening a PR) runs `.github/workflows/deploy-docs.yml` from the repo root, which builds with Hugo and deploys to Cloudflare Pages via `wrangler-action` (project `kusold-agent-skills`; PRs get `<branch>.kusold-agent-skills.pages.dev` previews). The workflow needs the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repo secrets.
- Known-benign build warnings: the portable-link warning for `docs/wiki-lint/index.md`'s link to `check_wiki.py` (a static file, not a content page — the link works); portable-link warnings for cross-links between docs pages written as `../{skill-name}/` (the partial's `GetPage` can't resolve sibling leaf bundles in any form — trailing slash, bare, or `index.md` — but the literal href resolves in browsers on the site and as a directory link on GitHub; `index.md` would 404 on the site, so keep the trailing slash); and the theme's own `.Page.IsNode` deprecation notice.
